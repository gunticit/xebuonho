# Kế hoạch: Nối thông suốt luồng Khách ↔ Tài xế (map thật toàn bộ service)

## Context — kết quả review

Luồng chỉ nối được **nửa đầu thật** (tạo cuốc → driver thấy → accept → FSM status → DB). **Nửa sau phía khách toàn mô phỏng:**

| Vấn đề | Chi tiết |
|---|---|
| Response parse sai | `POST /rides` trả `{"ride": {...}}` nhưng `RideModel.fromJson` đọc top-level → `ride.id=''` → **rating không bao giờ gửi** |
| Tracking giả | `tracking_screen` chạy Timer mô phỏng, driver name/plate hardcoded, **poll không gì cả** |
| `GET /rides/{id}` thiếu data | Không có driver_id/profile/lat-lng/fare_final — có poll cũng không biết ai nhận |
| "Driver found 3s" là giả | `booking_provider` delay 3s + fake ride khi lỗi |
| Cancel hỏng | `PATCH /rides/{id}/cancel` đi qua gRPC **stub** — không ghi DB |
| Driver app không sync | Không gọi `GET /driver/trip/current`, earnings/history render local mock; **không gửi location** dù endpoint có sẵn |
| Location 1-global | `UpdateLocation` lưu 1 biến chung cho mọi driver; `GetNearbyDrivers` trả **random** |
| Service khác | Express: không có backend; Scheduled: không có gì; Designated: `designated_mode` chỉ dùng để tính giá không persist; Chat: mock thuần; WS hub có sẵn nhưng app không có client |

## Phase A — Luồng ride chính chạy thật (priority cao)

**A1. Gateway `GetRide` mở rộng** (`postgres_repo.go` + `RideResult`): thêm `pickup/dropoff lat/lng` (ST_X/ST_Y), `fare_final`, timestamps, `customer_id`; LEFT JOIN users 2 lần → `driver {id, name, phone, vehicle_model, plate, rating(AVG trip_ratings, nullable)}` + `customer {name, phone}`; kèm driver location realtime từ per-driver map (A3).

**A2. Rider app nối thật**:
- `models/ride.dart`: parse `json['ride']` nested, `duration_minutes`, serviceType/vehicleType từ json
- `booking_provider.bookRide`: bỏ fake-ride khi lỗi (hiện lỗi thật), bỏ "simulated driver found 3s" — state chuyển theo dữ liệu server
- `tracking_screen`: poll `GET /rides/{id}` mỗi 3s — step theo status (`created`=đang tìm TX, `accepted`=đã nhận cuốc, `arrived`, `in_progress`=đang di chuyển, `completed`→`/complete`); driver card hiện **tên/biển số/rating thật**; marker xe dùng driver lat/lng thật khi có (fallback animation cũ); nút Huỷ → `PATCH /rides/{id}/cancel` thật
- `CancelRide` backend: repo thật — `UPDATE orders SET status='cancelled', cancelled_by, cancelled_at` với guard `customer_id=user AND status IN (created,accepted)` (bỏ gRPC stub)
- `trip_complete_screen`: fare từ `fare_final ?? fare_estimate` server; rating gửi với id thật (chain đã thông)

**A3. Driver app sync thật**:
- Gateway `UpdateLocation`: chuyển sang **per-driver map** `[driverID]LocationPoint` + mutex; `GetNearbyDrivers` đọc map thật (bỏ random) — rider map thấy vị trí TX thật
- `driver_provider`: khi online → Timer 10s gửi `POST /driver/location/update` (geolocator có sẵn); `acceptIncomingRide` gọi API thành công mới set trip; mỗi transition gọi API + sync response; thêm `loadCurrentTrip()` → `GET /driver/trip/current` khi online (khôi phục sau reload); xoá mock scheduling
- Dashboard: thẻ Thu nhập → `GET /driver/earnings` thật; `driver_history_screen` → `GET /driver/history` thật (api_service có sẵn methods cần thêm nếu thiếu)

## Phase B — Map các service còn lại

**B1. Express delivery (giao hàng)**: migration `000006_express_and_scheduled` — thêm `'express_delivery'` vào CHECK service_type; `delivery_screen` gọi `createRide(serviceType:'express_delivery')` thật (sender→receiver, parcel info vào notes) → driver thấy 📦, xử lý bằng FSM generic; đơn hiện trong Activity/historỵ.

**B2. Scheduled rides (đặt trước)**: cùng migration thêm `scheduled_at TIMESTAMPTZ`; `CreateRide` nhận `scheduled_at` → status `'scheduled'` (không lọt vào pending list); **worker goroutine** trong gateway (ticker 30s): `UPDATE orders SET status='created' WHERE status='scheduled' AND scheduled_at <= NOW()` → tự xuất hiện ở driver khi đúng giờ; `schedule_ride_screen` gọi API thật.

**B3. Designated driver (lái xe hộ)**: `CreateRideParams` + INSERT thêm `designated_mode/vehicle_type/plate` (cột có sẵn từ 000003); Flutter `designated_driver_screen` gửi `designated_mode` + thông tin xe thật (bỏ fake driver/ảnh mock lúc tạo).

**B4. Chat Khách ↔ Tài xế (minimal)**: migration `000006` thêm bảng `order_messages(order_id, sender_id, sender_role, message, created_at)`; gateway `GET/POST /api/v1/rides/{id}/messages` (JWT, chỉ participants); `chat_screen` nhận rideId, poll 3s + gửi thật (peer name từ ride detail).

**B5. Realtime WS push (hub có sẵn, thêm client)**:
- Gateway: event `EventOrderAccepted/StatusChanged` payload thêm `customer_id`; hub gửi `SendToUser(customer_id, ...)` thay broadcast; `/ws` verify JWT từ query token (web_socket_channel web không set header được)
- Flutter: thêm `web_socket_channel`; `NotificationService` mới connect `/ws?token=..` → cập nhật booking state tức thời khi accept/status; polling 3s vẫn chạy làm fallback

## Exclusions (ghi nhận, không làm trong đợt này)
Food merchant-linkage (Path B order-service + FSM food riêng — refactor lớn, food hiện workable bằng FSM generic); MQTT/EMQX thực (broker có, chưa client); FCM push.
